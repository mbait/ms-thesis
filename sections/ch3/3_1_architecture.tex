\section{Архитектура программного комплекса <<Модейлер>>}

\subsection{Общее описание платформы}

«Модейлер» --- программный комплекс для интерактивного моделирования и симуляции роботизированных устройств. 
Он позволяет моделировать как отдельные кинематические структуры, так целые системы промышленной 
автоматизации, включающие роботизированные устройства, автоматические машины и другие элементы производства. В 
области промышленной робототехники задачи, для которых применяется «Модейлер», охватывают проектирование 
роботизированных ячеек, отладку управляющих алгоритмов в режиме программного замкнутого контура (SIL), а также 
подготовку траекторий движения. В сфере исследовательских и образовательных применений платформа обеспечивает 
возможность экспериментов с моделями на основе описания роботов в формате URDF\footnote{Unified Robot 
Description Format — стандартный XML-формат, используемый в экосистеме ROS.} без необходимости развёртывания 
реального оборудования. На рисунке~\ref{fig:modeuler_screenshot} показан пример рабочей сцены в «Модейлере»: 
конвейерная линия с двумя промышленными манипуляторами.

\subsection{Многоуровневая архитектура}

Архитектура «Модейлера» организована по принципу строгого разделения ответственности. 
Рисунок~\ref{fig:modeuler_architecture} иллюстрирует взаимодействие компонентов системы. Ключевой особенностью 
является подключение физического движка \textit{dyphur} как \textbf{внешней независимой библиотеки}: он 
распространяется отдельно под лицензией Apache~2.0 и взаимодействует с ядром «Модейлера» через C++~API, не 
разделяя с ним Vulkan-устройство рендеринга.

\textbf{Уровень пользовательского интерфейса} реализован в виде двух независимых приложений. Приложение для
Windows построено на основе .NET~10 с использованием WPF, Fluent.Ribbon и AvalonDock. Приложение для Linux
реализовано на~C с использованием GTK~4. Оба варианта взаимодействуют с ядром исключительно через C~ABI.
Внешний вид интерфейса показан на рисунке~\ref{fig:modeuler_ui}.

\textbf{Уровень программного ядра} предоставляет стабильный интерфейс через заголовочный 
файл~\texttt{modeuler.h} (C-совместимый). Внутри ядра располагается менеджер Vulkan-устройства~--- 
единственный экземпляр \texttt{vsg::Instance} и связанное с ним \texttt{vsg::Device}, используемые для 
рендеринга через VSG. Физические вычисления dyphur выполняются на том же графическом процессоре через 
независимый контекст SYCL, не пересекаясь с потоком команд Vulkan.

\textbf{Уровень сцены и рендеринга} реализован на основе VulkanSceneGraph~(VSG). VSG организует трёхмерную 
сцену в виде ориентированного ациклического графа (DAG). Для загрузки 3D-геометрии используется 
плагин~vsgXchange; для разбора описаний роботов~--- библиотека~urdfdom.

\textbf{Физический движок dyphur} подключается как статически компонуемая библиотека. Ядро Модейлера вызывает 
C++~API dyphur для выполнения шага симуляции, получает обновлённые трансформации тел и применяет их к 
VSG-узлам сцены. Такая граница позволяет независимо развивать и обновлять оба проекта: Модейлер не привязан к 
dyphur жёстко и может быть перенесён на другой физический движок без изменения архитектуры.

\subsection{Кинематическая модель робота}

Описание робота в формате URDF задаёт дерево звеньев (\textit{links}) и сочленений (\textit{joints}). Каждое 
звено несёт информацию о визуальной геометрии, коллизионной геометрии и инерционных характеристиках; каждое 
сочленение определяет тип кинематической пары, её ось и пределы перемещения. При загрузке URDF ядро 
«Модейлера» транслирует описание в структуры dyphur: каждое звено становится телом (\texttt{BodyParams}), 
каждое сочленение~--- записью в \texttt{JointParams}, после чего данные загружаются на графический процессор.

\subsection{Программный интерфейс ядра}
\label{sec:core_api}

Программный интерфейс ядра спроектирован по принципу минимальной поверхности: пользовательский код работает 
только с непрозрачными дескрипторами и узким набором функций. Публичный C~ABI включает четыре группы функций: 
инициализация и завершение; управление сценой (создание, загрузка URDF); управление окном отображения; шаг 
симуляции и рендеринг кадра.

Функция \texttt{modeuler\_physics\_step} вызывает шаг dyphur с фиксированным значением $\Delta t$ (обычно 
1--2\,мс для реального времени), считывает обновлённые трансформации тел и применяет их к узлам сцены.
Затем \texttt{modeuler\_run\_frame} генерирует новый кадр. Привязки для управляемых языков формируются 
инструментом~ClangSharp, который генерирует код P/Invoke на~C\# для интеграции с WPF-приложением.

\subsection{Взаимодействие с ROS~2}

Интеграция с ROS~2 реализуется на двух уровнях. На уровне форматов данных: «Модейлер» использует URDF~--- 
официальный формат описания роботов в экосистеме ROS, а система координат соответствует конвенции фреймов~TF2. 
На уровне обмена данными: ядро «Модейлера» публикует состояние сочленений, одометрию и показания сенсоров 
через топики ROS~2, используя данные, полученные от dyphur по завершении шага симуляции. Это позволяет 
использовать «Модейлер» в качестве имитатора для управляющего программного обеспечения, работающего в штатной 
среде ROS~2 без изменений кода.

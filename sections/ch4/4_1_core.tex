\subsection{Интегратор}

Интегратор реализует симплектический метод Эйлера с дроблением шага на $n_{\text{sub}}$ промежуточных шагов. 
Каждый промежуточный шаг запускает одно вычислительное ядро, обрабатывающее все тела параллельно.

Симплектическая схема обновляет скорость \textit{до} позиции,
что гарантирует сохранение энергии системы при отсутствии диссипации:

\begin{align}
  \mathbf{v}(t + h) &= \mathbf{v}(t) + h\,\mathbf{g}, \\
  \mathbf{p}(t + h) &= \mathbf{p}(t) + h\,\mathbf{v}(t + h).
\end{align}

Кватернион ориентации обновляется через произведение с кватернионом угловой скорости и нормализуется после 
каждого шага.

Тела с нулевой обратной массой ($m^{-1} = 0$) и тела с установленным признаком \textit{Sleeping} пропускаются 
в ядре без ветвления по всему массиву.

\subsection{Широкая фаза: LBVH на графическом процессоре}
\label{sec:broadphase}

Широкая фаза реализует параллельную линейно-кодируемую BVH (Linearly-encoded Bounding Volume Hierarchy, 
LBVH)~\cite{karras2012lbvh}.

Алгоритм включает четыре последовательных прохода на графическом процессоре (рис.~\ref{fig:lbvh_pipeline}):

\textbf{Коды Мортона.} Каждая позиция тела нормируется относительно AABB сцены и квантуется в три 10-битных 
координаты, их смешивание образует 30-битный код Мортона. Код Мортона кодирует пространственную близость: телá 
с близкими кодами расположены в одном регионе пространства. В качестве ключа сортировки используется 64-битное 
слово $(\text{Morton} \ll 32) \,|\, i$, что делает сортировку стабильной при совпадении кодов.

\textbf{Построение дерева.} Алгоритм Карраса строит двоичное дерево из $n$ листьев и $n-1$ внутренних узлов за 
один проход: каждый внутренний узел $i$ определяет свой диапазон листьев через наибольший общий префикс кодов 
Мортона. Вся структура дерева вычисляется параллельно~--- по одному потоку на узел.

\textbf{Обновление AABB (level-synchronized refit).} AABB внутренних узлов вычисляются снизу вверх. Листовой 
проход задаёт AABB каждого листа. Затем выполняются раунды слияния: на каждом раунде запускается отдельное
вычислительное ядро, которое обновляет те узлы, оба потомка которых уже готовы (флаг \texttt{d\_flags}). Каждый раунд~--- 
отдельная постановка в очередь~--- гарантирует, что родитель читает только значения, записанные предшествующим 
ядром. Этот подход устраняет состояние гонки данных, которое возникало в прежней реализации, где два 
потока-потомка синхронизировались через атомарный счётчик: атомарная операция упорядочивала счётчик, но не 
гарантировала видимость fp16-записей AABB, сделанных первым потоком, для второго потока на CUDA. Раздельные 
постановки в очередь исключают эту зависимость и обеспечивают побитовую воспроизводимость на всех бэкендах. 
AABB узлов хранятся в формате fp16 для снижения потребления памяти вдвое.

\subsection{Узкая фаза}

Узкая фаза обрабатывает кандидатные пары параллельно.
Для каждой пары по типам форм выбирается один из алгоритмов (таблица~\ref{tab:narrowphase}).

\caption{Алгоритмы узкой фазы}

\begin{tabular}{lp{7.5cm}}
\toprule
\textbf{Пара форм} & \textbf{Алгоритм} \\
\midrule
Сфера--Сфера              & Аналитический (расстояние между центрами) \\

GJK и EPA реализованы с фиксированными массивами (64 вершины, 128 граней, 32 итерации для EPA), чтобы 
исключить динамическое выделение памяти в вычислительном ядре.

Каждая пара кандидатов обрабатывается одним потоком параллельно. Результаты (контакты) накапливаются в 
промежуточный буфер через атомарный счётчик, затем сортируются по ключу $(a, b)$ и переупорядочиваются в 
детерминированный список~--- это воспроизводит порядок, который дал бы последовательный проход, и сохраняет 
инвариант детерминизма.

\subsection{XPBD-решатель}
\label{sec:xpbd_impl}

Решатель реализует Гаусс--Зейдель по уравнениям раздела~2.4, распараллеленный методом \textbf{раскраски графа 
ограничений} (graph coloring)~--- подходом, применяемым в NVIDIA Newton/Warp и PhysX~5 TGS.

\textbf{Раскраска графа.} Ограничения (контакты и сочленения) разбиваются на цвета так, чтобы в одном цвете не 
было двух ограничений, совместно использующих \emph{динамическое} тело. Внутри цвета каждая пара ограничений 
задействует непересекающиеся тела~--- это позволяет выполнить весь цвет за одно вычислительное ядро \emph{без атомарных 
операций}. Цвета выполняются строго по порядку, что сохраняет связность Гаусса--Зейделя \emph{между} цветами. 
Этот подход детерминирован по построению: фиксированный порядок цветов и непересекающиеся записи.

Раскраска вычисляется жадным однопроходным алгоритмом в начале каждого кадра. Статические и кинематические 
тела ($m^{-1} = 0$) не включаются в граф: их поправки нулевые, поэтому они никогда не конфликтуют.

Алгоритм~\ref{alg:xpbd} описывает один шаг с параллельным выполнением по цветам.

\begin{lstlisting}[style=pseudocode,
  caption={Один шаг XPBD-решателя с раскраской графа},
  label={alg:xpbd}]
Вход: контакты C, сочленения J, тела B, шаг h, $n$ итераций
  раскрасить C $\cup$ J $\to$ цвета $\{K_1, K_2, \ldots\}$
  обнулить $\lambda_c \leftarrow 0$ для каждого контакта
  для $k = 1 \ldots n$:
    для каждого цвета $K_i$ (по порядку):
      // параллельно по ограничениям $K_i$:
      для каждого $c \in K_i$:
        $w \leftarrow w_A(\hat{n}) + w_B(\hat{n})$
        $\Delta\lambda \leftarrow -(d + \tilde{\alpha}\,\lambda_c)\;/\;(w + \tilde{\alpha})$
        $\lambda_c \leftarrow \max(\lambda_c + \Delta\lambda,\;0)$
        скорректировать позиции и ориентации тел A и B
  нормализовать кватернионы (параллельно по телам)
  обновить скорости: $\mathbf{v} \leftarrow (\mathbf{x} - \mathbf{x}_{\mathrm{prev}})/h$
\end{lstlisting}

Кватернионы нормализуются отдельным ядром после всех итераций. По завершении всех итераций скорости тел 
обновляются в соответствии с уравнением~\eqref{eq:vel-update}.

\subsection{Сцена и конвейер загрузки активов}
\label{sec:scene}

Модуль \texttt{scene/} реализует загрузку сцен из форматов SDF/URDF. SDF (Simulation Description Format) 
является родным форматом симулятора Gazebo и поддерживает вложенные модели, сочленения, материалы и 
геометрию столкновений.

Конвейер загрузки включает следующие этапы:
\begin{enumerate}
  \item Разбор XML через библиотеку \textbf{libsdformat};
    URDF конвертируется в SDF внутри библиотеки.
  \item Для невыпуклых коллизионных мешей выполняется
    \textbf{выпуклая декомпозиция} инструментом V-HACD~4.1:
    меш разбивается на $k \leq k_{\max}$ выпуклых оболочек,
    каждая из которых регистрируется как отдельная форма.
  \item Треугольные меши статических тел загружаются как \textbf{BVH-деревья}
    (построение на центральном процессоре по медианному разбиению, однократная загрузка на графический процессор).
\end{enumerate}

Координатная система SDF~--- $z$ вверх, гравитация $(0,\,0,\,-9{,}81)$\,м/с²,
без дополнительного преобразования осей.

\subsection{Пересечение лучей и датчики контактов}
\label{sec:sensors}

\textbf{Пересечени лучей.} Функция \texttt{ray\_query} выполняет пакетный обход BVH на графическом процессоре и возвращает 
ближайшее пересечение луча с телом: индекс тела, параметр $t$, нормаль в точке удара. Для обхода используется 
то же LBVH-дерево, что строится для широкой фазы~--- дополнительного BVH не требуется. Это является основой 
для симуляции сенсоров дальности (лидар, глубиномер).

\textbf{Датчики контактов.} После узкой фазы компонент \texttt{Contact\-Sensor} 
фильтрует выходной буфер по подписке на идентификаторы тел и делает контактные данные доступными Python-коду 
через нулевое копирование (DLPack / CUDA Array Interface): указатель на буфер устройства передаётся напрямую, 
без пересылки через центральный процессор.

\subsection{Выводы по разделу}

Ядро физического движка опирается на четыре архитектурных решения: level-synchronized LBVH обеспечивает 
параллельную широкую фазу без гонок данных; параллельная узкая фаза с сортировкой по ключу сохраняет 
детерминизм при полном распараллеливании на графическом процессоре; XPBD с раскраской графа обеспечивает 
детерминированную параллельную обработку контактов и сочленений; SoA-формат и слой \texttt{compute/} отделяют 
физическую логику от конкретного API графического процессора.
